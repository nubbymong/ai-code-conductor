## 2026-11-16 -- Helper local transport and session commands (2.1.3-beta.6, section A)

**Problem.** The beta.5 helper could hold a terminal, but only through files in a folder (`hold --dir`, `attach`, `end`), a stand-in written for probe P7. A local terminal that should outlive an app crash needs the real thing: a private endpoint per holder, a launch with a folder and an environment, an end that ends the whole process tree, a clock that ends a session nobody comes back to, and a way to find every held session at start-up.

**Change.**

- Protocol section 15 ("Local transport (protocol change 1)") in `docs/remote/helper-protocol.md`: the `hold` and `list` command lines, the endpoint rules, the record, the listing, the `local` capability and the `term.launch` / `term.attach` / `term.resize` / `term.detach` / `term.end` / `term.exit` messages with their limits. It is written for the app's client in section B.
- Transport (`helper/src/transport/`): a named pipe on Windows (`\\.\pipe\aicc-helper-<sid>-<32 hex>`, owned by the current user with an access list for that user only, first instance only, remote clients refused, opened by clients at identification level); a Unix socket elsewhere (`/tmp/aicc-<uid>/<sid>-<16 hex>.sock`, folder 0700 and a real folder of the user, socket 0600, every peer's user id checked). No network socket anywhere; the CI grep still guards `src/` and `tests/`.
- Holder process (`helper/src/serve.rs`, `request.rs`): at most 16 connections, a 10 s ack, 60 s idle, 5 s writes, strict per-type schemas, the newest attach replaces the older, a connection that falls behind is told to attach again, and the away clock (default 120 s, from start, each detach and each dropped connection).
- Launch (`helper/src/pty/`): `argv[0]` an absolute path, the folder, and the environment given as the whole environment (only `TERM` is added on Unix when absent). Windows starts the program suspended in a kill-on-close job object; Unix ends every process in the child's session with hangup, then kill after 2 s. When the first process exits, the rest of its tree goes too, and the holder keeps the last output and the exit code for the app.
- Records and list mode (`helper/src/store.rs`, `client.rs`, `pids.rs`): `<store>/<sid>.json` written whole, read strictly; `list --store` prints every session and removes the records of holders that are gone (process not running; endpoint empty or answering without the record's nonce; or, on macOS and Windows when the endpoint gives no clear answer, a process id that now names a process started more than 60 s after the record).
- Closing a connection after a last message (`replaced`, `busy`, `term.detached`, `term.ended`): the first CI run showed macOS losing bytes the client had not read yet when the holder cut the socket both ways (Linux and Windows kept them). The holder now stops writing first, so the client reads the message and then the end of the stream, and cuts both ways 2 s later; before it exits on `term.end` it waits up to 2 s for the app to close.
- From the first review round: typed input goes through a queue of 64 frames to its own writer thread, so a program that stops reading can never hold the lock that ending the session needs (more input then gets `busy`). On Unix, ending signals every process in the session, not only the first process group (a shell job in its own group that ignores hangups is ended too). An attach again on the same connection drops output still queued for the earlier one. The store's lock file (`.lock`) covers a holder's check-and-write and list mode's removal, which re-reads the record under the lock. The hello line and every frame have one deadline for the whole of it, and a Unix connect is nonblocking with a timeout, so a full backlog is "no clear answer", not a hang.
- From the second review round: on Unix an end never signals a session whose program has been reaped and whose session is empty, since its id may name another process by then, and a terminal that fails after its child started ends that child. Each limit on a frame or a write is for the whole of it: a frame's JSON is at most 4 KiB before the ack and 64 KiB once a session is launched, a payload's buffer grows only as its bytes arrive, and a whole message has 5 s to be written. macOS ignores `MSG_DONTWAIT` on a send (a slow reader stretched one 16 MiB message to 12 minutes in CI), so there a send asks `poll` first and sends no more than the socket's low-water mark, which a writable socket always has room for. macOS also takes a listen backlog of 0 as its largest. Once typed input is refused, the rest of the connection's input is refused until the app pings, so the program never sees a gap. One thread ends a session: the away clock decides under the state lock, an attach or a launch during an end gets `not-found`, every `term.end` gets its own `term.ended`, and an attached connection gets `term.exit` when another one ends the session. Each write of the record says what is attached at that moment, `running` never replaces `exited`, and nothing is written once the end has begun. On macOS a full listen queue no longer reads as a gone holder. On Windows a client that came and went before the accept no longer frees the pipe's name, and every later instance is checked for the user-only list. `hold` exits 3 when a holder for the session is already running; `--detach` passes on the holder's own message, starts it in the store folder, and says when the holder could not leave the app's job. The unused peer process id is gone, and a thread that cannot be started is an error, not a panic.
- From the third review round: the Windows pipe names the user as its owner (`O:<SID>D:P(A;;GA;;;<SID>)`), and a later instance is joined only if the pipe's owner, not only its list, is the user's, since an owner may always change the list. An attach counts its live-output forwarder while it still holds the state lock, so an end claimed during a slow replay waits for the program's last output instead of dropping it. On macOS and Windows, a record whose endpoint gives no clear answer (a crashed holder's socket on macOS) is stale when its process id now names a process that started more than 60 s after the record's `started`; list mode and a new holder for the session both use that rule (`store::holder_gone`), so on macOS a reused id no longer keeps a session id stuck, unless the new process got the id within 60 s of the record. Section 15 now says what the app does with typed input when the stream ends before its `pong`: it sends none of it again and attaches again. On Unix, the `tree_gone` check at the top of `end_tree` is now the one place that keeps a finished session's id from being signalled, and a test fails without it.
- From the fourth review round: macOS reads a start with the `kern.proc.pid` sysctl, as `ps` does, instead of `proc_pidinfo`, which refuses another user's process; a reused id often lands on one of root's. libc does not declare `kinfo_proc` for Apple, so `pids.rs` declares its first fields and checks the size the kernel returns and the id. Linux no longer uses the rule. It worked a start out from the boot time, which moves with every change to the clock, so after a forward step of more than 60 s (a VM saved and restored gives hours) a live holder whose endpoint gave no clear answer read as gone, and list mode removed its record and socket. A crashed holder's socket on Linux is refused or missing, which is already stale.
- `hold --detach` waits for the holder's record and reports a holder that exits early. The self-test gained a `local-transport` round trip. The fake CLI answers `pwd`, `env NAME` and `spawn-grandchild` for the tests.
- `helper/src/dirhold.rs` and the `attach` / `end` commands are gone. Probe P7 (answered 2026-11-15, ADR-030) drives them, so its README and script header now say it needs a 2.1.3-beta.5 `helper-windows` artifact to run again.
- Fixtures: `helper/fixtures/local.json` (requests, a launch frame, records, listings, endpoints, limits; vectors tagged by OS where paths differ), read by `helper/tests/fixtures.rs` and by an independent reader in `tests/unit/scripts/helper-fixtures.test.ts`, which also pins section 15's numbers to the document and to the Rust constants.

**Decisions.** `detach.rs` stayed, because `hold --detach` needs it, and it is not a transport: it already does what P7 proved, and now returns the child so an early exit is reported. When the first process exits on its own, the rest of its tree is ended too, so nothing is left running with no terminal and no holder to reach it. A frame's JSON limit drops once a session is launched, since only a launch is large. The start-time rule is used only when the endpoint gives no clear answer: a holder that answers is never gone, and a gone endpoint is already stale. The rule runs only where a process keeps a fixed start stamp, macOS and Windows: no later change to the clock moves it. The 60 s of slack cover the clock being set back in the moment between a holder's start and its record. The rule misses a process that got the id within a minute of the record; macOS hands ids out in turn, so that is not likely. A process that started before its record was written is never taken for another, since a holder always starts before it writes its record. The rule runs on Windows too, though there a gone pipe already settles it. Linux skips it: its start moves with the clock, and a crashed holder's socket there is refused or missing, which is already stale. No new crate: `windows-sys` gained features only, so `Cargo.lock` still holds 12 packages. The CI network grep does not cover `std::os::unix::net`, which the Unix transport uses for its socket; that module is local only.

**Tests.** `helper/tests/probe_transport.rs` drives a detached holder from a client in the test, as the app will: list, hello and ack, launch with a folder and an environment (a variable set only on the holder must not reach the program), attach, type, resize, a second connection replacing the first from an offset, detach, a third replaying from 0, end with the program and its grandchild gone, the exit path, the away clock, stale records, a second holder refused, and the refusals. `helper/tests/hold.rs` adds the tree and environment checks in process. The second round added a unit test for each fix it could pin down: no signal to a session that is over (`pty/unix.rs`), a frame whose bytes never come, the smaller JSON limit (`frame.rs`), the input gate, the record's `running` and the exit code 3 (`serve.rs`), the store's exact 0700 (`store.rs`), a refused peer, a full backlog in list mode, a slow reader against the whole-message limit (`transport/unix.rs`), and a client that came and went, a pipe someone else made, and the same slow reader (`transport/windows.rs`). The third round added: a pipe with the user's list and another owner is refused (`transport/windows.rs`), a finished session's id is never signalled even when a live group holds it again (`pty/unix.rs`), this process's start time reads in the right unit (`pids.rs`), and a record whose id names a later process is stale only when its endpoint gives no answer (`store.rs`); `helper-fixtures.test.ts` pins the new descriptor, the 60 s and the input rule. The fourth round added: launchd's start, a process of root's, can be read on macOS (`pids.rs`), and on Linux a record whose endpoint gives no clear answer is kept whatever its process started (`store.rs`). The fifth round added: on Linux a crashed holder's socket, still there with nothing listening, makes the probe say the holder is gone although the record's process id runs, and list mode removes the record and the socket file (`transport/unix.rs`). That refusal is the one thing that clears such a record on Linux, and a short-lived commit that read it as no clear answer turned the test red. The start-time test in `store.rs` is renamed `a_record_whose_id_names_a_later_process_is_stale_only_where_a_start_is_read`, so its name holds on every OS. Rust runs in CI only; the vitest files run locally through the locked runner.

**Owed.** The adversarial pass on the local pipe and the terminal launch is owed before stable, as the plan agreed. The app side (start-up re-attach, the Machines page) is section B.
