## 2026-11-17 -- Terminal font with GPU rendering, the Saved/Running tab row, the notifications placeholder (2.1.3-beta.7, C1)

Three renderer fixes in one PR (plan 2.1.3-beta.7, section C1).

**#313: GPU terminal text in a small sans font.** Bisected on the test VM (WINDOWS_1, session 0, the released 2.1.3-beta.6, GPU rendering on, a CDP probe of the live terminal's WebGL atlas). The cause is not the one the plan named first, and not the weight:

- The 2D canvas in Electron 44.11.3 ignores a `font` value that starts with whitespace and stays on its default, `10px sans-serif`. `' 450 13px "JetBrains Mono"'` is dropped; `'450 13px "JetBrains Mono"'` is kept. Every variant with a leading space was dropped, on a fresh canvas and on an OffscreenCanvas.
- `@xterm/addon-webgl` 0.19 builds each glyph's font as `${fontStyle} ${fontWeight} ${size}px ${family}`, and fontStyle is '' for upright text. So the whole atlas was drawn in 10px sans-serif, inside cells xterm had measured correctly with JetBrains Mono (7.8 px).
- A fresh atlas built after the font had loaded was still sans (load timing is not the cause). Weight 400 was still sans (the weight is not the cause). The same fresh atlas with the canvas font string trimmed drew JetBrains Mono.
- Electron moved from 44.5.1 to 44.11.3 on 2026-11-14 (#662), first shipped in 2.1.3-beta.1, which fits the first reports on 2026-11-16.

Fix: `terminal/canvasFontTrim.ts` wraps the 2D context `font` setters once, so the string reaches the browser trimmed (whitespace around a CSS value is insignificant). `installWebglWithRecovery` installs it before it creates the addon. xterm, the addon and the atlas are untouched, and the atlas is not rebuilt more often. The plan's font wait ships too, because the VM showed the race is real once the string is accepted: the face finished loading only 34 ms before the first glyph (a renderer reload). TerminalView now waits for the regular and bold faces before its first initTerminal call (capped at 1.5 s, never rejects). A face that is already loaded starts on the first frame as before. No weight change (orchestrator default; the VM proved the weight is not the cause).

Proof on a build of the branch head (unpacked, on the VM): cold start, GPU on, WebGL renderer, two terminals including bold text drawn in JetBrains Mono; the font is loaded before the first cell measure and the first glyph. Not done: a cold start after a VM reboot. The VM is shared with the track B idle measurements, and a reboot would bring up an autologon console session that was not there. The plan leaves the after-restart confirmation to the owner's PC.

**#315: Saved/Running tabs at UI scale 1.3 and the 200 px sidebar.** Each tab may shrink (min-w-0), its label truncates, the count badge never shrinks, and the row is a named query container (`@container/panel-tabs`). Below 13.75rem of row width the icon drops out and the tab's padding and gap tighten. Measured on the VM: "Running" is 2.99rem, the badge 0.75rem plus about 6 px a digit, the icon 13 px; the default 256 px sidebar at scale 1.0 gives a 14.9rem row, so the default look is unchanged. VM matrix (scale 0.8, 1.0, 1.3 by width 200, 256, 420, both tabs): every tab has scrollWidth <= clientWidth and its badge inside the sidebar; labels are whole everywhere except scale 1.3 at 200 px, where "Running" shows as "Run..." (the two labels need 22 px more than the row has). The sidebar minimum is unchanged.

**#314: the Hooks Gateway "Desktop notifications (coming soon)" checkbox** is gone, and the card no longer calls the gateway the foundation for upcoming notifications. It used no state of its own. app-knowledge, tips, the Feature Guide and README never mentioned it; the 1.3.x changelog lines stay as history. The three Codex lines of the card text are unchanged (WP1 manifest line count).
