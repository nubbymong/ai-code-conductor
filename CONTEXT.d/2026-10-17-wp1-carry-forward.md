## 2026-10-17 -- 2.1.2 carries the 2.1.1 WP1 evidence forward on a declared file list (ADR-027)

**Decision.** The owner chose to ship the macOS headless PATH fix as 2.1.2, a stable patch with no beta, under a new recorded rule: 2.1.1's WP1 evidence carries forward when the only changes are a declared small file list with named regression tests and green CI on all three operating systems (`docs/wp1/owner-decisions-2026-10-17.md#CF1`). ADR-027 is the rule.

**Branch.** `release/v2.1.2` is cut from `v2.1.1` (main), not from beta: beta is already past the binding with a non-neutral change, and main is not in beta's history. On it: the 2.1.1 security record, the six commits of the fix (fb7e9574, 30143f19, be7cea92, 245dc5db, 7441f8b5, 5cd12a3a), the rule, check 5 of the release gate, their review and attack fixes, the docs, and the 2.1.2 version and changelog entry.

**The rule.** `tests/wp1/carry-forward.json`, as committed at HEAD, lists every non-neutral path changed since boundHead with its regression tests; the candidate case judges it in place of its final assertion (`carryForwardProblems`, `committedCarryForward`, `bindingVerdict` in `tests/wp1/binding.ts`). With no declaration its verdict is the one before, but every candidate run now refuses a declaration it cannot read from HEAD, and the repository-wide checks (packaging, `src/` reach, builder config) run only at the candidate phase with a declaration committed, so one merged back to beta does nothing there. The release gate's check 5 requires ci.yml's push run on the released commit completed and its three Test jobs (one per operating system) green on the released commit, the declared PR merged as that commit (a merge of its head onto the base) with an ADR-009 PASS at its final head, and the base tag the repository's latest published release, made by release.yml, on the base commit. On every stable cut the gate also reads the paths changed since boundHead from git itself. The `gate` job reads with `contents`, `issues`, `pull-requests` and `actions`.

**Review and attack.** A spec review, a quality review and two attack passes (gate bypass; fail-closed and platform parity) led to: a committed-only read of the declaration in the suite and the gate, refusing its path in another case (a file of the same name in another folder is ignored); only Markdown and the manifest under neutral paths; a frozen set of gate files once a base has the rule; a per-line size cap, a 64 KiB byte cap and counted paths that leave out only release tooling proven unpackaged; a `src/` reach scan that reads through comments; the merge-parents, latest-published-release and ci.yml-provenance checks; exact paging; and the gate reading the paths changed since boundHead from git on its own, with the suite's neutral rules shared from `release-gate.mjs`. ADR-027 lists them and their mutants; the size used at the 2.1.2 cut is in ADR-027 and CF1.

**What's New.** Adding the 2.1.2 changelog entry broke two tests that read the real changelog (one assumed 2.1.1 is newest; the What's New drift guard required curated lines for the newest release). Both tests were changed, and 2.1.2 is named there as a fixes-only release (the coordinating agent's choice), rather than adding a curated What's New line, which would have needed 17 paths.

**Not yet done.** The declaration file itself is committed after the PR is opened, when its number is known; until then the candidate case is red on the branch, as designed. The adversarial pass, the Mac runtime check under a test user, and CI on the PR and on the merge to main follow.

**Next qualified stable.** The stale rule fails it until `tests/wp1/carry-forward.json` is deleted.
