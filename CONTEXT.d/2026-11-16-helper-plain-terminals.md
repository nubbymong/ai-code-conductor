## 2026-11-16 -- Session helper in the installer; plain and partner terminals through it (2.1.3-beta.6, section B)

**Problem.** The Rust session helper (helper/, ADR-030) could hold a terminal past the app, but nothing shipped it and the app never started it, so a Terminal only tab or a partner terminal still died with the app.

**Change.**

- Packaging: the release workflow builds the helper (`cargo build --release --locked` in helper/) in the Windows, macOS and Linux packaging jobs, before packaging. Each platform section of package.json's `build` copies the one release program to `resources/helper/` (electron-builder signs it with the app on Windows and macOS). `scripts/verify-bundled-helper.mjs` (`npm run verify:helper`, after `verify:package` in each job) fails the package when the helper is missing, is not a program for that OS, says another version than helper/Cargo.toml, or has other files beside it. `tests/unit/scripts/helper-not-shipped.test.ts` became `helper-packaging.test.ts`: only the release program ships, nothing else of helper/. ci.yml's release/* packaging does the same: the macOS Test job and the Windows build job build the helper before they package and run `verify:helper` after, so the `windows-installer-<sha>` and `macos-dmg-<sha>` artifacts of a release/* pull request run carry it (the VM installer check uses that Windows artifact). The package scripts in package.json end with `verify:helper` too. release.yml also checks the packaged helper's own signature: on Windows a valid signature by the pinned signer, with a timestamp; on macOS `codesign --verify --strict`, the app's own team and the hardened runtime. On macOS the helper carries the app's entitlements (electron-builder applies `entitlementsInherit` to every Mach-O and has no per-file entitlements); signing it on its own with none is a follow-up (threat model 3.1).
- Install: at start-up the app copies the installed helper into a per-user folder outside the install folder (Windows `%LOCALAPPDATA%\AI Code Conductor\helper`, macOS `~/Library/Application Support/AI Code Conductor/helper`, Linux `~/.ai-code-conductor/helper`), one folder per version and hash. Before every run of the copy it checks the copy's SHA-256 against the installed file; a mismatch is copied again once, a second mismatch marks the helper failed and starts nothing through it. Old version folders no holder runs from are removed. Threat model 3.1 and 3.10 say what this covers and what is not there yet.
- The app side is `src/main/session-helper/`: the protocol client (frames, hello, records, listings, launch checks against helper/fixtures), one connection per holder, `HelperPty` (node-pty's IPty over a holder), the manager, and its wiring. pty-manager.ts changes 11 lines and gains none: the shell-only local spawn calls `spawnPlainPty` with the renderer's plain mark, and a re-attached held terminal gets no cd line and no launch line. Off, `spawnPlainPty` is node-pty's spawn with the very same arguments.
- Setting: Settings, General, Terminal, "Plain terminals through the session helper", off by default (`plainTerminalsThroughHelper`). On, a Terminal only tab and a partner terminal start through a holder. Only those carry the mark (`plainTerminal`, set in TerminalView and checked in the spawn schema): a sign-in tab, an install or update command tab and the first-run install terminal always start the usual way. Agent sessions, SSH, elevated tabs, a string argument line and a launch the holder would refuse (for example two environment names that differ only in case) start the usual way.
- Crash: a running mark in the helper folder tells a crash from a normal quit. After a crash, start-up attaches every held terminal at once from the records in the helper's store, before the copy and the listing (each record's own hello proves its holder, so a slow listing cannot use up the two minutes away); a tab restored with the same id shows its terminal and scrollback again. Its folder line and first-run command wait until the take-over is known: a take-over that fails starts a new shell the usual way, and that shell gets both. A held terminal no tab shows is listed on the Machines page, where Re-attach opens a Terminal only tab bound to it (the binding is kept in the helper folder) and End ends it. A normal quit sends every holder its end and removes the mark at once; will-quit waits at most 1.5 s for the answers. One the quit could not reach (a terminal still starting) ends by its away clock, and the next start ends it too.
- The connection follows protocol section 15 for typed input: a ping after every 16 frames or 1 MiB and nothing more until its pong, and the frames a holder refused (`busy`, while the program is not reading) are sent again, so the program never gets input with a gap. A pong that does not come closes the connection.
- A connection that drops while the terminal runs (the holder closes one that fell 256 chunks behind) is attached again from the last byte seen, at most three times a minute, with what was typed and not yet sent going first. One decoder runs across attaches, so a character split at the cut is still whole. A terminal that cannot be shown any more (an attach unanswered, the holder gone, a fourth drop inside a minute) reads as ended in its tab (exit -1), and its holder is ended too.
- A crash with a helper that cannot be set up still shows the held terminals again and lists them; switched off with terminals still held, the page lists them and End works, and the Services row reads stopped only once nothing is held. A copy that could not be put in place is tried again by a terminal opened a minute later. `hold` exiting 3 (a holder for that terminal runs already) connects to it, and a record left by a holder that is gone no longer stops a new one.
- Services: a sixth row, Session helper (host `helper`), with how many terminals it holds and no restart. The Machines page gets its source from the manager (setMachinesSource).
- Feature Guide: the Machines section and the known issues say what the setting does and when a terminal starts the usual way.

**Not in this change.** The live SSH matrix (pty-manager.ts is in its list, though only the local branch changes) and the VM check (setting on, app ended from Task Manager, reopened within two minutes, then after three, then a normal quit) are run by the release owner. The survival after a crash is a Windows promise in this beta (probe P7).

**Tests.** `tests/unit/main/session-helper-flow.test.ts` (one terminal against the fake holder: input pacing and resend, attaching again, the ends), `session-helper-install.test.ts` (the folders, the busy-file wait, old version folders), `tests/unit/main/session-helper-protocol.test.ts` (the client against the helper's shared vectors), `session-helper-manager.test.ts` (against a fake holder: off is today's spawn, the branch, the copy and its hash, a crash re-attach, tabless terminals, a normal quit, the Machines and Services mapping), `session-helper-app-wiring.test.ts`, `session-helper-pty-site.test.ts`, `tests/unit/renderer/held-terminal-tab.test.ts`, `machines-page.test.tsx` (Re-attach shows the named tab), `tests/unit/scripts/helper-packaging.test.ts`, `tests/unit/scripts/verify-bundled-helper.test.ts`, and the updated service registry, Services panel and spawn-site inventory cases.
