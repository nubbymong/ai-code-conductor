## 2026-11-16 -- Session helper in the installer; plain and partner terminals through it (2.1.3-beta.6, section B)

**Problem.** The Rust session helper (helper/, ADR-030) could hold a terminal past the app, but nothing shipped it and the app never started it, so a Terminal only tab or a partner terminal still died with the app.

**Change.**

- Packaging: the release workflow builds the helper (`cargo build --release --locked` in helper/) in the Windows, macOS and Linux packaging jobs, before packaging. Each platform section of package.json's `build` copies the one release program to `resources/helper/` (electron-builder signs it with the app on Windows and macOS). `scripts/verify-bundled-helper.mjs` (`npm run verify:helper`, after `verify:package` in each job) fails the package when the helper is missing, is not a program for that OS, says another version than helper/Cargo.toml, or has other files beside it. `tests/unit/scripts/helper-not-shipped.test.ts` became `helper-packaging.test.ts`: only the release program ships, nothing else of helper/. ci.yml's release-branch packaging is not changed here (section D owns ci.yml in this beta).
- Install: at start-up the app copies the installed helper into a per-user folder outside the install folder (Windows `%LOCALAPPDATA%\AI Code Conductor\helper`, macOS `~/Library/Application Support/AI Code Conductor/helper`, Linux `~/.ai-code-conductor/helper`), one folder per version and hash. Before every run of the copy it checks the copy's SHA-256 against the installed file; a mismatch is copied again once, a second mismatch marks the helper failed and starts nothing through it. Old version folders no holder runs from are removed. Threat model 3.1 and 3.10 say what this covers and what is not there yet.
- The app side is `src/main/session-helper/`: the protocol client (frames, hello, records, listings, launch checks against helper/fixtures), one connection per holder, `HelperPty` (node-pty's IPty over a holder), the manager, and its wiring. pty-manager.ts changes three lines and gains none: the shell-only local spawn calls `spawnPlainPty`, and a re-attached held terminal gets no cd line and no launch line. Off, `spawnPlainPty` is node-pty's spawn with the very same arguments.
- Setting: Settings, General, Terminal, "Plain terminals through the session helper", off by default (`plainTerminalsThroughHelper`). On, a Terminal only tab and a partner terminal start through a holder. Agent sessions, SSH, elevated tabs, a string argument line and a launch the holder would refuse (for example two environment names that differ only in case) start the usual way.
- Crash: a running mark in the helper folder tells a crash from a normal quit. After a crash, start-up attaches every held terminal at once from the records in the helper's store, before the copy and the listing (each record's own hello proves its holder, so a slow listing cannot use up the two minutes away); a tab restored with the same id shows its terminal and scrollback again. Its folder line and first-run command wait until the take-over is known: a take-over that fails starts a new shell the usual way, and that shell gets both. A held terminal no tab shows is listed on the Machines page, where Re-attach opens a Terminal only tab bound to it (the binding is kept in the helper folder) and End ends it. A normal quit sends every holder its end and removes the mark at once; will-quit waits at most 1.5 s for the answers. One the quit could not reach (a terminal still starting) ends by its away clock, and the next start ends it too.
- Services: a sixth row, Session helper (host `helper`), with how many terminals it holds and no restart. The Machines page gets its source from the manager (setMachinesSource).
- Feature Guide: the Machines section and the known issues say what the setting does and when a terminal starts the usual way.

**Not in this change.** The live SSH matrix (pty-manager.ts is in its list, though only the local branch changes) and the VM check (setting on, app ended from Task Manager, reopened within two minutes, then after three, then a normal quit) are run by the release owner. The survival after a crash is a Windows promise in this beta (probe P7).

**Tests.** `tests/unit/main/session-helper-protocol.test.ts` (the client against the helper's shared vectors), `session-helper-manager.test.ts` (against a fake holder: off is today's spawn, the branch, the copy and its hash, a crash re-attach, tabless terminals, a normal quit, the Machines and Services mapping), `session-helper-app-wiring.test.ts`, `session-helper-pty-site.test.ts`, `tests/unit/renderer/held-terminal-tab.test.ts`, `tests/unit/scripts/helper-packaging.test.ts`, `tests/unit/scripts/verify-bundled-helper.test.ts`, and the updated service registry, Services panel and spawn-site inventory cases.
