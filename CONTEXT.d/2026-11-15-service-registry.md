## 2026-11-15 -- One service registry with honest Services rows (2.1.3-beta.4, PR 3)

**Problem.** The Services panel was fed by a hand merge of four sources in `src/main/ipc/service-health-handlers.ts` (the hooks supervisor, the logging supervisor, PTY integrity and the Watchdog), with restart special-cased by id beside it. A row could be on one of two hosts only, and a new row was called an in-process fallback by default. So the Watchdog, which has no child process at all, read as a fallback, and so did a hooks gateway or a logging worker that was merely starting. The MCP server was fixed text ("in-process :19333 (next phase)") whatever the server was doing and on whatever port. The usage index had no row.

**Change.**

- `src/main/services/service-registry.ts` is new. It is one list of rows (hooks gateway, session logging, Tokenomics, Watchdog, MCP server): how each row is read, and where a restart of it goes. The three supervisors stay as they are, over the shared `Supervisor` base; nothing is merged and the registry forks nothing. `src/main/index.ts` hands it getters, and both the push and the GET handler read it.
- A registered service always has its row. One that is not there to ask reads stopped (hooks off, logging off, usage index not started). Before, logging switched off had no row, and neither did a Watchdog that was not set up yet. One whose source throws reads crashed with the reason ("row could not be read: ..."), and the other rows still arrive; before, one throw failed the whole snapshot for the pill, the panel and the sleep indicator at once. A PTY source that throws leaves its block out and puts a line in the log.
- The row ids and labels are one shared pair of constants (`SERVICE_ID`, `SERVICE_LABEL` in `src/shared/service-health.ts`), used by the registry, the three supervisors, the Watchdog and the panel, so an owner and the registry cannot disagree on a row's id.
- Host kinds (`src/shared/service-health.ts`): `utility-process`, `in-process`, `in-process-fallback` and `helper`. The fallback kind is kept because the hooks gateway can still fail open to the main process; only its supervisor sets it. `helper` is kept for the per-machine helper and no row uses it. `createInitialHealth` now takes the host; there is no default.
- Tokenomics: `TokenomicsSupervisor` reports a row (stopped, starting, listening, crashed, restarting, degraded), tells the Services view when it changes (a shutdown included, so the row and the pill do not keep their last state when the service is shut down while the app runs), and has a manual restart. Until now a usage index that ran out of restarts stayed down until the app was relaunched. A restart asked of a supervisor that was never started is refused with `stopped`, as its row reads, so a restart never becomes a first start. The row's in-flight figure is the queries the worker has not answered yet. The row follows its counters: a changed Events count (from a health beat or a finished sweep) and every query entering or leaving in-flight (sent, answered, failed or timed out) is pushed, at most once per 250 ms with a trailing push so the last value lands (the timer is unref'd and cleared at shutdown). A worker a restart has replaced can no longer change the row: its late health, progress and completion messages are ignored (its log lines are still forwarded; an answer to a query is matched by request id, and a restart rejects every pending query, so a replaced worker has none left to settle). A shut down worker leaves no uptime on the stopped row.
- MCP server: a real row from the server's own `isMcpServerRunning()` and `getMcpPort()`, with the start error that `index.ts` already caught. The server itself is not changed. The row has no restart, because the server lives in the main process and open sessions hold connections to it. The row is pushed once the start settles, which is what moves the pill off "Starting" when nothing else is pushing.
- The shared row has an optional `measured` block (`cpuPercent`, `filesTouchedLastScan`, `sampledAt`), and the panel shows it when it is there. Nothing fills it yet.
- Panel (`src/renderer/components/ConductorServicesPanel.tsx`): the fixed MCP text is gone; a stopped row other than hooks says "stopped" where it said "disabled"; with more cards the panel now scrolls inside the window. Each card shows only the counters its row keeps, so a figure nobody counts never shows as a real zero: the hooks gateway shows all of them; session logging all but its child's event-loop stalls; Tokenomics shows uptime, in-flight, restarts and events; the Watchdog uptime, in-flight and events; the MCP server none. Uptime reads the same way on every supervised card (hooks, logging, Tokenomics): it is the age of the current child, it starts when that child reports itself up (bound or ready; the same hooks child bound a second time after the switch is turned off and on keeps its age), so a crash restart or a press of Restart starts it over, and it reads empty while the child is down or not up yet. The hooks and logging rows also show no PID while their child is down (a hooks child has none until it binds; a logging worker has the PID it was forked with until it exits), and the hooks row shows no event-loop stalls of a child that is gone. The restart count, last error and event count stay across restarts. A hooks row that has fallen back to the main process shows no PID and no child stalls (the card treats any row that runs inside the app this way, and the supervisor clears both figures when it fails open). The main loop's stalls show on every card that has counters ("Jank m", or "Jank m/c" where the child reports its own).
- Title-bar pill (`src/renderer/components/ConductorHealthPill.tsx`): with five rows always present, a row that is switched off (logging off, the Watchdog not in use) no longer turns the pill grey; it is grey only when every row is stopped. A row that is starting or restarting reads "Starting" or "Restarting" (amber) where it read "Degraded", which now means only a degraded row. "Fallback" and "Down" are as before.

**What crosses the preload.** No channel was added, removed or renamed, and `src/preload/index.ts` is untouched. The snapshot the two service-health channels carry changed: `host` can also be `in-process` or `helper`; a row can carry `measured`; the `services` list always holds the five rows above, in that order. The restart channel now answers `not-restartable` for the MCP row and `unknown-service` for an id that is no row, and accepts `tokenomics`; it answers `stopped` for Tokenomics when that service was never started. A row whose source cannot be read arrives as `crashed` with the reason `row could not be read: <reason>`, and the log tail can carry one `pty-read-failed` error line when the PTY source cannot be read.

**Not in this change.** The Tokenomics off switch and the measured figures come in the next two PRs. The Tokenomics card shows no process id, because the supervisor is not told its worker's; the measured figures will need it.

Each new case was red on the old code or under a mutant of the new code. The twelve cases the handlers test held before are covered in the registry and merge tests; the WP1 ledger under `tests/wp1/` records the mapping for each baseline test file whose cases changed.
