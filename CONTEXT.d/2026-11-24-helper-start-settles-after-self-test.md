## 2026-11-24 -- Session helper: a start settles only once its self-test has; the Node 20 folder clean-up failure is root-caused

CI run 45341253799 (windows-2025, Test part 4 of 4, Node 20.20.2) failed in session-helper-flow.test.ts's teardown with ENOTEMPTY on the helper copy's version folder, after every assertion passed. That job and the green run 45343419232 each logged "session-helper-manager: left ... behind (ENOTEMPTY)" for 8 folders. A catch-and-log on the beta.17 aggregate (ef56a05c) answered it without a cause; this replaces it (aicc_planning#417).

- **The cause.** `bringUp` (src/main/session-helper/manager.ts) began the self-test with `void`, so `start()` settled while the self-test still read the copy (`copyMatches` -> `sha256File`, a read stream). The teardowns wait for every start, then call `rmSync`.
- **Why CI only.** On Windows, Node 20's unlink leaves a file that another handle has open listed until that handle closes, so its folder cannot be removed; Node 24 (local runs, and the app's runtime) removes the name at once. `rmSync`'s retries sleep synchronously, and a read stream needs the event loop to finish and close, so retries cannot help. A stream that already reached 'end' is harmless: its close is already queued off the event loop.
- **Measured.** A read-stream trace at each teardown's `rmSync`: before, 12 tests in session-helper-manager.test.ts reached it with a self-test read not yet ended; after, none in 3 runs. Shown on Node 20: CI run 45360479242 (windows-2025, Test parts 1 to 4 of 4, node v20.20.2), with every session-helper catch removed, logged no ENOTEMPTY and no "left ... behind" line, and all five session-helper files passed.
- **The change.** `bringUp` keeps the self-test it begins and settles once it has; a start that tests a failed helper again settles once that test has. The helper reads ready at the same moment as before. The app never waits for `start()` (both calls in app-wiring.ts are `void`). Anything that awaits `start()` from now on also waits for the self-test (up to its 25 s limit): wait for the ready state instead.
- **Tests.** "a start settles only once the self-test it began has..." is red on the old code, and red at its second check with only the `bringUp` half. The swallowed clean-up error is gone from the teardowns of the session-helper-manager, -update-keep, -old-copies and -agent-screen tests. tests/wp1/fake-cli.test.ts keeps its own (spawned fake CLIs, EBUSY: another cause). tests/unit/main/insights-run-terminal.test.ts keeps its own too: it awaits its start, so its self-test is already waited for, and its catch also covers the report terminal and the resources folder (another subject).
