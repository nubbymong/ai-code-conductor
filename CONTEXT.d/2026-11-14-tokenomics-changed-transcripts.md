## 2026-11-14 -- Usage index: read only the transcripts that changed (planning #302, #306)

**Problem.** The usage worker listed every folder under `~/.claude/projects` and every Codex sessions folder, and asked the size of every transcript in them, on each watcher event (after 0.75 s) and on a 5 s timer. No file was read twice (each has its size, time and offset kept in the index), so the cost was the walk itself. With 25 working sessions it kept the worker at about a fifth of a core.

**Change** (`src/main/tokenomics/tokenomics-worker.ts`).

- A Claude transcript the watcher reports, written or newly made, goes into a set, and the next sweep reads only the files in that set. No folder is listed.
- The whole tree is still walked at start, on a re-index, on an event that names no transcript (no file name, a folder, a deleted file, a file that is not a transcript), on any event in a Codex sessions folder, and every 5 minutes as the net for anything the watcher missed.
- A full walk that leaves work behind runs again until every file is read. A file is read one budget per pass (16 MB of a Claude transcript, 64 MB of a Codex rollout), so a large first index or the one-off Codex account re-read takes many passes. As first written (PR #655) the next walk was then up to 5 minutes away, one budget of each file every 5 minutes. Now the next pass follows after the usual 0.75 s pause while every file left with bytes moved its cursor, so each pass reads further and the passes end when the bytes do. A pass that left bytes without moving a cursor (a short read) and a walk that failed part-way are retried by the 5 s timer, never at once. Once a walk has read everything, nothing walks again until a walk is due.
- A reported transcript that is a link is left alone and starts no walk. The full walk skips links; the report was checked with stat, which follows one, and is now checked with lstat.
- The files that could not be read are kept by path. Every sweep used to start that count again, and a changed-files sweep visits only the reported files, so after any reported change the count read none and the Usage page's note about transcripts that could not be read came and went between full walks. A changed-files sweep now takes a file out only when it tries it again, and a full walk starts the list again.

**Cost.** Before: one full walk per watcher event and per 5 s tick, so at least 12 a minute and up to 80 a minute while sessions write. After: a tick with nothing reported lists no folder and asks about no file, and a reported transcript costs two size checks and the read of its new bytes. In the test tree 59 timer ticks in a row list and read nothing, and the 60th, at 5 minutes, walks once.

**Not in this change.** Codex folder events are not narrowed: any of them still starts a full walk. A new file or folder under the projects folder can still start one, where the watcher reports the folder as well as the file (not measured per platform). A transcript that grows by more than one budget between two sweeps still makes the next sweep a full one. The rest of planning #306 is left alone: rows for files that no longer exist are not pruned, the root folder is not resolved to its real path, and there is no off switch.

**Tests.** `tests/unit/tokenomics/tokenomics-worker-changed-files.test.ts`, the real worker on a plain Node run with an in-memory stand-in for the index database: only the reported transcript is read and no folder is listed; the full walk at start and on each kind of event that names no transcript, a Codex folder event included; nothing on the 5 s timer until the 5 minute walk; the repeat until drained for a Claude transcript and for a Codex account re-read, and that it then stops; no repeat at once after a short read or a failed walk, and the timer's retry; a link, simulated on every platform and real where the platform lets a test make one; the count of transcripts that could not be read, across changed-files sweeps. The repeat cases, the link case and the count case failed before their fixes. `tests/unit/native/tokenomics-dirty-sweep.native.test.ts` (from PR #655) checks the totals against the real database in the CI native suite; it was not run on the development machine.
