## 2026-11-27 -- 2.1.3-beta.20: the cut (version, user-facing surface sweep, docs)

Phase 6 of the approved beta.20 plan. Branch `fix/b20-p6-cut`, from the
beta.20 aggregate at b071a3fd. It describes what the code at that head does;
text the phase 5 fix round changes later is for that round to restate.

Version: `package.json` and the two root version fields of
`package-lock.json` are 2.1.3-beta.20, set by hand as for beta.12 (no
`npm version`, no install). The helper crate stays 0.1.0; its one beta.20
build (field mode's keys) rides in the installer as before.

The sweep (AGENTS.md "User-facing surface sweep"):

- What's New and CHANGELOG.md: the 2.1.3-beta.20 entry; `npm run changelog`
  leaves CHANGELOG.md in sync. Warnings restate the three standing ones, add
  that a sign-in made on a machine stays on that machine, and say what going
  back to beta.19 leaves behind.
- Feature Guide reference and Ask Conductor (`app-knowledge.ts`): Switch
  Account on helper tabs, the renewal of a still-valid sign-in, a new
  "Accounts on a machine" part of the Machines section (Sign in on that
  machine, Accounts here, the not-signed-in notice, Remove, Adopt), the helper
  tab starting on its config's account. Five known issues: reviews not on a
  remote session's machine; no Codex accounts on machines; no Lend; the
  primary account's Refreshing (the owner's exact text); the CLI's welcome
  screens on a first launch in a new account folder.
- Tips: new tips for Sign in on a Linux machine, Switch Account on a helper
  tab and the review's model, effort and footer; the Usage tip says a signed-in
  Claude account renews itself. No tip was for a removed feature.
- Feature Guide cards (`training-steps.ts`): Multiple Accounts (the grid, the
  renewal), Code Review (model, effort, the footer) and Machines (Accounts
  here, the notice, Switch Account). The Account usage page has no card of
  its own: the Multiple Accounts card is its home. The guided tour needs
  nothing (its rail step names the Usage page without describing it).
- README: the grid, renewal, review model and effort, accounts on machines,
  and the outbound list. PRIVACY.md: a row for the renewal's address
  (`platform.claude.com`, which replaced `console.anthropic.com` in phase 4)
  and "Read usage again" for "Retry". USER_GUIDE.md: the Usage page.
- Screenshots: not retaken (no VM yet). No README image shows the Account
  usage page or the Machines page. The Feature Guide's
  `src/renderer/assets/training/step-machines.jpg` shows the Machines page
  before Accounts here, and should be retaken on the VM, with new shots of the
  Account usage grid and a machine's card for the README.
- Docs: ADR-030 D7 notes that sign in on this machine ships first and lending
  (#443) comes next. ADR-031 was checked against the code; four lines now say
  what the code does (the Claude effort list with no model chosen, the check of
  an effort against the model the environment names, "not confirmed" for the
  default, and the 5-minute default review time). The helper protocol documents
  field mode's `--keys` (identity from `.claude.json`, plan and expiry from
  `.credentials.json`, no token ever printed, one JSON object of strings and
  integers, nothing printed for a missing or foreign-owned file).

Tests changed because the text they pinned is now superseded: the Multiple
Accounts card's old "section per assistant" line (app-knowledge test), and the
tip provider-mark list (two new tips are Claude Code's).

Left as found (not beta.20's): the onboarding Accounts step still says
accounts apply to local sessions only, which is true while the remote sessions
preview is off, its default. docs/USER_GUIDE.md still says the app never
refreshes a login token itself, which was already untrue before this beta
(the Usage page has renewed lapsed tokens for some time); that sentence is a
statement about the app's security posture, so it is for the owner to reword.

Owed before stable: the ADR-009 passes for the beta.20 phases, as each phase's
fragment records (aicc_planning#320). Not desktop-verified.
