## 2026-11-14 -- One service supervisor (planning #307, point 8; bugs B8 and B9)

**Problem.** The hooks gateway, session logging and the usage index each ran their forked child under their own copy of the same lifecycle: fork, notice the exit, back off, count restarts, give up after five, manual restart, shutdown. None of the copies knew whether the service was wanted. Two bugs came from that.

- B8: turning hooks off did not stay off. The Settings toggle told the child to stop, but every child start (a crash restart, a Services-panel restart) told the new child to start again.
- B9: a restart budget never came back during a run. Five unrelated crashes over days pushed hooks into its in-process fallback and left logging or the usage index degraded until the app was restarted (logging could be revived by hand from the Services panel; hooks in fallback and the usage index could not). The usage index also kept every message sent while its worker was not listening, with no limit.

**Change.** `src/main/services/supervisor.ts` is now the only place that forks a supervised child, watches it exit, backs off, counts restarts and decides to stop. The three services keep their names and their own parts (the messages they exchange with their child, their health row, their buffers, their query layer) and hold no restart counter, no backoff and no restart timer.

- Desired state. A service is wanted on or off. Off drops a pending restart, a crash while off is not restarted, and a manual restart is declined with reason `disabled`. Hooks is the one service with a runtime switch: the proxy's `start()` and `stop()` tell the supervisor. Off shows the service as `stopped` on the Services panel (the panel already says "Hooks are disabled in Settings" for that state and greys the Restart button). On again tells a child that is still running to start, as before, or forks one when none is running. A child that answers "bound" after being turned off is told to stop again. Turned on again with no child running is a fresh start: it is shown as `starting` and logged as `enabled` then `child-up` ("turned on"), even while earlier crashes are still counted. A bind failure reported while hooks are off is not shown as a crash and leaves no error on the card.
- Budget recovery. Once a child has reported itself up (hooks: bound; logging and the usage index: ready) and has then run five minutes without exiting, the restart count and the backoff go back to zero, and the service's log says so. A child that never comes up, or exits inside the five minutes, gives nothing back, so a crash loop still ends in fallback or degraded exactly as before. Only the current child's own report counts: a "bound" or "ready" still draining out of the pipe of a child that has been replaced or has exited is ignored. It is not shown as listening, nothing held is replayed to a worker that has not opened yet, and it starts no stable period.
- A fork that fails. After the first start, a fork that throws (on a crash restart, a Services-panel restart, or hooks turned on again) is treated as a child that died at birth: the service shows `crashed` with `fork failed: <reason>`, the backoff forks the next one, and the budget still runs out. Nothing is thrown at the Settings toggle or the Services panel, and the service is never left with no child and nothing on its way. The first start still throws to its caller, as before.
- Usage-index buffer. While the worker is not listening, only the newest message of each kind is kept (pricing, saved configs, Codex account folders, reindex): at most four. Each kind replaces the worker's whole state for it, and a second reindex while one is running was already ignored by the worker.

**Kept as it was.** Fork helpers, child entry points, spawn arguments, environment, the messages sent at spawn and their order (hooks: rebind, replay secrets, start; logging: open, not-indexed windows; usage index: open), start order and shutdown order in `index.ts`, the backoff steps (250, 1000, 4000, 4000, 4000 ms), the default budget of five, the log codes and texts already there, hooks' fail-open, logging's permanent degrade and its manual revival, and the usage index's own rule that a ready worker starts the backoff over at once. The hooks toggle while in the in-process fallback is untouched (the proxy drives the in-process gateway directly).

**Small differences worth knowing.**
- Restart timers no longer keep the event loop alive on their own (the usage index's never did; hooks' and logging's did). In the Electron main process this changes nothing.
- A manual restart lets go of the old child before killing it, so an exit fired by the kill itself is never taken for a crash of the new child.
- A crash restart whose fork throws used to escape from the restart timer as an uncaught exception (and a logging restart by hand threw at the Services panel). Both are now a counted crash that the backoff retries.
- A saved config that was created and removed again while the usage-index worker was not listening no longer gets a label row (only the newest config list is sent). A restarted worker already behaved this way, because it is opened with the newest list.

**Not done here.** The class names `ServiceSupervisor`, `LogSupervisor` and `TokenomicsSupervisor` stay (the last two are mocked by name in about forty test files); they are services on the one supervisor now, and a rename is a separate, test-only change. Logging and the usage index are still decided once at start (no runtime switch), so their desired state is always on. The hooks child stops its heartbeat and jank monitor when told to stop and does not start them again when told to start; that is older than this change and is left for its own fix. The query layer that logging and the usage index both carry (ids, timeouts, reject on exit) is still two copies.

**Tests.** `tests/unit/services/supervisor.test.ts` (the supervisor alone), `tests/unit/services/service-supervisor-desired-state.test.ts` (hooks: B8 and B9), `tests/unit/logging/log-supervisor-budget.test.ts`, and two new groups at the end of `tests/unit/tokenomics/tk-supervisor.test.ts` (buffer bound, budget). The existing supervisor cases pass unchanged. A review round added cases to the same four files for a fork that fails, a replaced child's late report, hooks turned on again after crashes, and a bind failure while off. `tests/unit/main/spawn-site-inventory.json` loses the entry for the usage index's old `this.spawn(` method, which no longer exists.
