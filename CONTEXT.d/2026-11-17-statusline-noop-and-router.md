## 2026-11-17 -- Statusline ticks that change nothing are skipped, and one listener serves every session (2.1.3-beta.7, plan section B2)

**What.** aicc_planning#304, renderer only. Three changes:
- `updateSession` compares plain objects and arrays by value (`sameStatusValue`, the guard from PR #654, which was never merged and is superseded by this change). A statusline tick hands it `usageBuckets` and `rateLimitExtra` as fresh objects from IPC, so the old `!==` check called every tick a change, even a tick whose whole payload repeated. Anything that is not a plain object or array is still compared by identity. Past depth 6 a value counts as changed, which also stops a cyclic value from recursing forever.
- `RateLimitBar` is memoized. Its props are primitives, so a bar whose figures did not change skips its render, and with it the `formatResetTime` calls that B1 found to be the renderer's top self-time function at N=25 busy on beta.6. Its reset text also depends on today's date (a reset later today shows the time only), so the bars check the date: one timer for all mounted bars, aimed just past local midnight but never waiting more than 15 minutes, and again whenever the window is shown. A timer runs late after a system sleep and does not move when the clock or time zone changes; the cap bounds how long a stale date can stay. A check that finds the same date renders nothing.
- `src/renderer/lib/sessionBroadcastRouter.ts`: the statusline, effort, watchdog and account-identity channels each have one preload listener for all sessions. Each TerminalView used to add its own listener per channel, so with N sessions every message crossed the context bridge N times and N-1 handlers threw it away. The router hands a message only to the handlers of its own session, drops one whose session has no handler, and releases the channel on the last unsubscribe.

**Decisions.**
- Every subscription is its own entry, even for the same handler function. During a remount handover the old and the new view of a session can both be subscribed for a moment, and each unsubscribe removes only its own entry.
- The router reads the bridge when it binds: on the first subscribe, and on the first one after the channel was released. It never rebinds a live channel. In the app `window.electronAPI` never changes (a preload change reloads the whole page, which also resets this module). The three hook test files that install a fresh mock per test now unmount their hooks after each test, so the channel is released and the next test binds its own mock.
- The four hooks no longer check the session id themselves: the router does, and its tests prove it.
- `RateLimitBar` is a named export, as the repo's rule asks of a file with several exports. The inner function keeps the name `RateLimitBar`, because `scripts/perf` reads CPU profiles by function name.
- No preload, IPC or main change, so no adversarial pass, and nothing in the SSH live-matrix radius.

**Measured on the test VM** (2026-11-17, B1's harness, one run each, shortened: N=25 only, 60 s idle settle, 60 s windows, 5 min busy settle, 90 s renderer profiles, no A/B/A, no ablations). Before: the installed 2.1.3-beta.6. After: this branch's first commit, 58a5e7e0 as it stood on ad3c58e2 (rebased since), built on the VM with `electron-builder --dir` without the session helper binary (off by default) and started through `CCC_STAGE_APP_EXE`. The date check and the review fixes came later and were not measured.
- 90 s renderer profile at N=25 busy: `RateLimitBar` 30.3 ms self and 788.8 ms inclusive before, 0.0 and 59.4 after; `formatResetTime` self 754.4 and 59.4 ms. At N=25 idle, `RateLimitBar` 0.0 ms self and 53.1 ms inclusive before, 1.3 ms self and 5.1 ms inclusive after: the idle self time is the one figure that rose, by an amount this single run cannot tell from noise. The preload `handler` (one call per listener per message) 1.20 and 0.61 ms per second busy, 0.16 and 0.07 idle.
- Renderer CPU, % of one core: 24.87 and 23.62 busy, 3.36 and 3.37 idle; renderer main thread busy (CDP task time) 16.7 and 15.4 % busy. One run each, inside the 1.3 to 2 point spread B1 saw between all-on runs, so no CPU gain is claimed.
- The plan's acceptance (`RateLimitBar` under 50 ms self in a 90 s profile at N=25; 333 ms on 2.1.2) was already met on beta.6: 30.3 ms here, 17.8 and 14.1 ms in B1's 60 s profiles.
- The store guard skips a tick only when its whole payload repeats. Live ticks from Claude Code usually differ: its payload carries the session's total cost and duration, which grow while it works, and the hook copies both. The fake CLI on the VM changes its figures every tick too. So the guard's real gain is unmeasured and likely small; it mostly skips exact re-sends. The memo is the part with a measured effect: the drop in `formatResetTime` comes from bars rendering when the session they show ticks, not when any of the 25 does.
