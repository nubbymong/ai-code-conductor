## 2026-11-17 -- Statusline ticks that change nothing are skipped, and one listener serves every session (2.1.3-beta.7, plan section B2)

**What.** aicc_planning#304, renderer only. Three changes:
- `updateSession` compares plain objects and arrays by value (`sameStatusValue`, the guard from PR #654, which was never merged and is superseded by this change). A statusline tick hands it `usageBuckets` and `rateLimitExtra` as fresh objects from IPC, so the old `!==` check called every tick a change, replaced the `sessions` array, and re-rendered everything that reads the whole array (the multi-account footer among them) on every tick from every session. Anything that is not a plain object or array is still compared by identity, and past depth 6 a value counts as changed.
- `RateLimitBar` is wrapped in `React.memo`. Its props are primitives, so a bar whose figures did not change skips its render, and with it the `formatResetTime` calls that B1 found to be the renderer's top self-time function at N=25 busy on beta.6.
- `src/renderer/lib/sessionBroadcastRouter.ts`: the statusline, effort, watchdog and account-identity channels each have one preload listener for all sessions. Each TerminalView used to add its own listener per channel, so with N sessions every message crossed the context bridge N times and N-1 handlers threw it away. The router hands a message only to the handlers of its own session, drops one whose session has no handler, and releases the channel on the last unsubscribe.

**Decisions.**
- A session id holds a set of handlers, not one: during a remount handover the old and the new view of a session can both be subscribed for a moment, and each keeps its own unsubscribe.
- The router binds again when the bridge's `onUpdate` function changes, releasing the old listener first. In the app it never changes; a test that installs a fresh `window.electronAPI` mock, or a dev hot reload, does. Without this, the existing hook tests that leave a hook mounted would keep the first test's mock bound.
- The four hooks no longer check the session id themselves: the router does, and its tests prove it.
- No preload, IPC or main change, so no adversarial pass, and nothing in the SSH live-matrix radius.

**Tests.** `tests/unit/renderer/session-store-noop-ticks.test.ts` (6 cases: the guard from #654, plus a render check on the memoized bar) and `tests/unit/renderer/session-broadcast-router.test.ts` (7 cases). Before the change the store file failed 4 of its 6 cases (the equal-values case on its assertion, the two `sameStatusValue` cases because the export did not exist, the bar case on its assertion) and the router file failed to load (the module did not exist). Each of the 13 cases was then seen red under at least one of nine mutants, each run on the two files through the locked runner: guard back to `!==`; router delivering to every session; the beta hooks restored with the router present (25 listeners per channel); no release on the last unsubscribe; bar not memoized; non-plain objects compared by value; release that forgets the listener; no rebind on a new bridge; any two arrays equal. The StrictMode case first passed under the forgetful-release mutant because the fake bridge kept its listeners in a Set and the router always passes the same function: the fake now wraps each registration, as preload's `onChannel` does.
