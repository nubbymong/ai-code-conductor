## 2026-11-15 -- PR numbers check: the SSH radius, pty-manager.ts and its cap (2.1.3-beta.5, section C)

**Problem.** Two numbers that decide how much a pull request costs lived only in prose. The live SSH matrix is owed when a PR touches one of eight files (AGENTS.md, "SSH statusline changes need the live SSH matrix"), and nothing told the author or the reviewer whether it did. And ADR-030 capped `src/main/pty-manager.ts` at 8,128 lines, but #681 (terminal-only SSH tabs, merged after the ADR was written) had already taken it past that, and nothing would have noticed a PR that grew it further. ADR-030's own SDLC table says "a check that prints these numbers on every PR is its own slice, after beta 4."

**Change.**

- `scripts/ci/pr-numbers.mjs` (zero dependencies, like `change-scope.mjs`) reads the PR's changed paths against its base (the merge commit's first parent, depth-2 checkout) and writes a table to the job summary: whether the PR touches the eight radius files (and which), the length of `src/main/pty-manager.ts` against the cap (and the change against the base), and "live SSH matrix: owed", "check (pty-manager.ts only)" or "not owed". `pty-manager.ts` is in the radius only for its SSH branch, its sentinel parsers and its statusline routing (AGENTS.md), so a PR whose only radius hit is that file gets "check": owed only if it changed those parts, not for its local branch or its length, and an unsure author runs it. Any of the other seven files, or changed paths that could not be read, is "owed".
- It fails only when pty-manager.ts grows past the cap: over the cap, touched by the PR, and not shorter than on the base. A file that is already over the cap is not blamed on a PR that leaves it alone or shortens it. The `cap-override` label lets a growing PR pass, and the summary says so. A file that cannot be read fails; a deleted file (the remote deletion in ADR-030) is under any cap, but a missing file counts as deleted only when the changed paths list it, so a job started in the wrong folder fails instead of passing. Anything it cannot read for certain (the changed paths, the base) is treated as touched: the matrix is owed.
- The cap is the constant `PTY_MANAGER_LINE_CAP` in `scripts/ci/pr-numbers.mjs`, the one source of the number: it is the length of the file on beta when the check was added (ADR-030 gives the starting value once, with its date), and the merge sets the constant to the file's length on beta at that moment. It only goes down. That is a reminder, not enforcement: when a PR shortens the file, the summary and a warning annotation say to lower the constant to the new length, and the job still passes. The job fails only for growing past the cap.
- Owed before this merges: a `cap-override` label must exist in the repository, since the summary tells authors to add it (an owner step; nothing here creates it).
- `ci.yml` gains an always-on job named `PR numbers`, ubuntu, one step. Its only condition is the event (`pull_request`), like `Desktop test gate`: it decides inside, so it can never leave a check waiting and may become a required check later. Labels come from the event, so adding or removing `cap-override` runs it again. The action is pinned by commit. The `Test (os)` jobs are not touched.
- ADR-030 is corrected: the Context list says "over 8,000 lines", and the SDLC table gives the starting length once (dated 2026-11-15, with one sentence saying #681 raised it from 8,128 before the check existed) and points at the constant for the cap.

**Tests.** `tests/unit/scripts/pr-numbers.test.ts`: the radius list equals the eight backtick paths of the AGENTS.md paragraph (extracted, not copied); the table over fixed path lists (a renderer-only PR, one line in `ssh-tmux.ts`, each radius file on its own, look-alike paths); the cap (grow, at the cap, shorter, label, already over, deleted, unreadable, fail closed); `main()` with a fake git and event file; the ADR points at the constant, states the dated starting length once and mentions 8,128 once; pty-manager.ts alone is "check", every other radius file is "owed"; a missing file passes only when the changed paths list it; the job always starts on a pull request with no step condition. Each new case was red under a mutant of the new code.

**Not in this change.** It is not a required check. It does not read the live matrix result, only says whether one is owed (the matrix needs real hosts). It does not read labels from the API, so a run started again by hand replays the labels of its first event; a label change starts a fresh run. AGENTS.md is not edited.
