## 2026-11-15 -- Snap's window picker asks for Screen Recording too, the inactive-account sentence names Make active, and a tab shows a refusal without its log marker

Found by the independent review of the 2.1.3-beta.5 release PR (#691), which checked every user-facing claim against the merged code.

**Snap, Window.** The Screen Recording check (`screenCaptureAllowed`, #690) guarded the region capture only, while the release text said "Snap checks the Screen Recording permission first". The window picker listed windows without asking, so with the permission off it showed blank or desktop-only thumbnails. `listWindows` (`src/main/screenshot-capture.ts`) now runs the same check first, with the app window as the message's parent (`screenshot-handlers.ts` passes it): without the permission the user gets the same sentence and Open System Settings, and the list is empty. `not-determined` still lets the list run, so macOS shows its own prompt the first time. `captureWindow` is unchanged: it is only reached from a listed window, and a capture without the permission comes back empty, which it already answers with null.

**The inactive-account sentence.** The refusal said "is switched off" and "switch it back on in Settings, Accounts", but the Accounts menu has no switch: it shows an Inactive badge and the items Make inactive and Make active (`AccountsPanel.tsx`). The sentence (`inactiveAccountRefusal`, `account-profiles.ts`) now reads: The Claude account "NAME" is inactive, so nothing was started on it. Choose another account (for a tab, use Switch Account in its right-click menu), or use Make active on "NAME" in Settings, Accounts. The known-issues entry in `app-knowledge.ts` quotes it word for word (a test holds that).

**A refusal in a tab.** A managed Claude launch is always deferred, so its refusal reaches the tab through `writeDeferredSpawnFailureReason` (`pty-manager.ts`), which wrote the error's message as it was: `[profiles] refusing a managed Claude launch: On a Mac, ...`. The marker is for logs and for callers that tell a refusal from another failure; cloud agents, Insights and headless runs already showed the sentence alone (`launchRefusalText`). The tab now does too. One line changed in `pty-manager.ts`, outside its SSH branch, sentinel parsers and statusline routing, so the live SSH matrix is not owed for it (the PR numbers check reads `pty-manager.ts` alone as "check"); the file's length is unchanged (8367, the cap).

**Tests.** `screenshot-snap-guard.test.ts`: the window list with the permission off (the sentence, no windows asked for), granted, not decided and off macOS. `pty-held-launch-replaced-pty.test.ts`: a refused Restart shows the capitalised sentence and no `[profiles]` marker. The sentence assertions in `account-launch-refusals`, `insights-project-gate-refusal`, `cloud-agent-account-refusals` and `sentinel-unreachable-timing` follow the new wording. Each new assertion was run red against its mutant (the check removed; the old `raw` line restored).
