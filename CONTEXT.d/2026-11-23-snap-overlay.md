## 2026-11-23 -- Snap's own overlay, one window per display (beta.16 A2, aicc_planning#402)

- `src/main/snap/overlay.ts` exports `openSnapOverlays(displays)` and `Rect` (ADR-030 D3 and D4, S8 step 2). One frameless, always-on-top window per display at its DIP bounds, no taskbar entry; its page `src/renderer/snap-overlay.html` shows the display's picture with a crosshair, the dragged rectangle with its size in the picture's pixels, and a bar with Whole screen and Cancel. Enter takes the rectangle, Escape cancels. No drawing tools, no window capture.
- The answer: `{ id, rect }` (DIP within display `id`, clamped to it in main), `{ id, whole: true }`, or `null` for a cancel (Escape, Cancel, or a close request such as Alt+F4). A failed overlay REJECTS with `SnapOverlayError` and its `reason` (load-failed, renderer-gone, window-closed, no-ready, window-failed, bad-display, no-displays, busy), so the caller can tell a failure (the previous Snap takes the press) from a cancel (nothing). A null alone could not carry the reason.
- Main owns the way out: Escape is taken in main (`before-input-event`) before the page; a failed main-frame load, a gone renderer, a window destroyed without a close request, or no `ready` within 5 s each close every overlay window and reject. A close request is not prevented (that would also cancel an app quit): it answers null.
- The ready bound (5 s) was set from snap-e2e's first run (CI 45260050397): the previous Snap's overlay was on screen 783 ms after the press. Each open logs `[snap] overlay pages ready on N display(s) in X ms`, the reading to set it from again.
- The overlay preload `src/preload/snap-overlay.ts` exposes two calls (`ready`, `answer`) and imports only `electron`: a sandboxed preload must build to one file, and a module shared with the main preload would become a chunk it cannot load. A build of both preload entries showed two standalone files, each requiring only electron.
- The picture goes to the page as a JPEG data URL (quality 92): shown only, never cut from; encoding is far quicker than PNG on main's thread.
- `SCREENSHOT_REGION_SELECTED` and `SCREENSHOT_CANCELLED` (declared, used nowhere) are gone; `SNAP_OVERLAY_READY` and `SNAP_OVERLAY_ANSWER` replace them.
- Snap's engine (A1, feat/snap-own-capture-windows) merges this branch and calls `openSnapOverlays`; snap-e2e drives the overlay on the runner's desktop and keeps a picture of it mid-drag.
