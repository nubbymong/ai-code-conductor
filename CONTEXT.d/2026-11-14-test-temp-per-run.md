## 2026-11-14 -- A finished test run removes only its own temp folders; the Copilot notes point at the release process

**Problem.** When a vitest run ended, `tests/global-setup.ts` removed every `ccc-vitest-*` folder in the machine temp folder, including the working folders of another run going on at the same time (two agents, or a watch run beside a full run). `.github/copilot-instructions.md` also still gave the old stable route (merge `beta` to `main`, then `npm run release -- --stable --no-bump`), which is not the release-branch model in `AGENTS.md`.

**Fix (test-side only, nothing shipped).**
- `tests/helpers/vitest-run-tag.mjs` is new. Global setup makes an eight-digit hex tag for the run and puts it in the environment before any worker starts, so the workers inherit it.
- The two folders the harness makes straight under the machine temp folder now carry it: the per-worker root (`tests/helpers/test-tmp.ts`) and the isolated home (`tests/helpers/home-guard-core.mjs`) are named `ccc-vitest-<tag>-...` and `ccc-vitest-<tag>-home-...`.
- The teardown (`sweepAfterRun` in `tests/global-setup.ts`, a named export so a test can run it on a scratch folder) removes only the folders that carry its own tag, and a folder that will not go at once is retried up to five times. With no well-formed tag it removes nothing, so it can never fall back to the old sweep.
- A folder left by a worker that was killed during an EARLIER run is no longer removed by name by a later run. Instead the teardown also removes any `ccc-vitest-*` folder not modified for 24 hours whose run is over, judged by an owner file `ccc-vitest-owner-<tag>.json` (the vitest main process pid) that global setup writes and the run's own teardown removes; a folder whose owner is still alive stays however old it is (a watch run can last for days), and a folder with no owner file keeps the plain 24-hour rule.
- A process that does not start under global setup (the native and live configs have none) still gets the plain `ccc-vitest-` name. Nothing removes that folder when its own run ends any more; the 24-hour sweep of a later unit run takes it.
- `tests/unit/test-isolation/run-tag-teardown.test.ts` is new. It plants another run's folders, an untagged one and unrelated ones in a scratch folder under the worker's own temp root, and checks that only this run's go. It runs `sweepAfterRun` on a scratch folder (this run's folder and a stray `mock` go; another run's, an untagged one and unrelated ones stay), checks the 24-hour sweep with folders whose modified time was set back, and checks that the tag reached the worker.
- `.github/copilot-instructions.md`: the stable-release line is replaced by a pointer to `AGENTS.md`, section "Release Process", and the `main` line now says `main` is updated only by the stable promotion PR from a `release/vX.Y.Z` branch, not by PRs from `beta`. The procedure itself is not copied there.

**Checked.** The new test is red on the old code (the tag never reaches the worker), red with the old match put back into the removal step (another run's folder is taken), red with the old remove-every-`ccc-vitest-*` loop put back into `sweepAfterRun`, and red with the 24-hour sweep left out of the teardown or made to ignore age. A folder named like another run's, planted in the real temp folder, is removed by the old teardown and survives the new one.
