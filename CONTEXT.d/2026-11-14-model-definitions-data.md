## 2026-11-14 -- Model definitions are data the app reads at start-up

**Problem.** A new model needed a release. Until one shipped, Sentinel kept saying "Claude Code offers MODEL, but it is not in the model picker", and the model could not be picked by its own name.

**Decision (owner, 2.1.3-beta.1, approved on the canvas).** The model file is read once at start-up from a branch of this repository that holds only that file, so adding a model is one edit there and no release.

**To add a model.** Edit `model-registry.json` on the `model-data` branch of `nubbymong/ai-code-conductor`. It is the same file, in the same format, as `resources/model-registry.json` on `beta`, including its `"formatVersion": 1` line. Keep the two the same: the copy on `beta` is what a fresh install, or an install that is offline, starts with.

**How it works.**
- `src/main/model-registry-remote.ts` reads `https://raw.githubusercontent.com/nubbymong/ai-code-conductor/model-data/model-registry.json`: https only, a redirect followed only within that host (each hop checked by the app, never by the transport), 256 KB at most whatever the reply says about its length, an answer within 5 s, no credentials, never a throw.
- `src/main/model-registry-data.ts` checks the text with zod, strictly: only the fields the bundled file has (an unknown field anywhere refuses the whole file), every string bounded and free of control and hidden characters, ids and aliases and efforts from a small alphabet that cannot read as a flag or carry a second line, colours only a theme variable or a six-digit hex, prices finite and in range, a format version (a higher one than this version reads is ignored). A model the bundled file carries cannot be moved to the other assistant.
- A pattern is plain text. `literalPattern` (`src/shared/model-registry.ts`) is the one rule both the check and the matcher read: the check admits only patterns it accepts, and the matcher matches every such pattern as text. Nothing from a fetched file is compiled into a regular expression. The bundled patterns (`^gpt-`, `^o`) are of that form and match as before. A pattern in the user's own overlay that is a real expression is still read as one.
- `src/main/model-registry-service.ts` joins the file to the bundled one (`mergeModelData`): the file's models first and winning per id, a model only the bundled file has kept after them, so the file can add and correct but never take a model away. The user's overlay still goes on top. Every reader (pickers, effort checks, prices, Sentinel, the renderer's store) gets the result through the same `getRegistry` and the same reload push as before.
- A good file is kept as the last good copy in the app's config folder (`CONFIG/model-data.json`), and is checked again, the same way, each time it is read back. The service never makes that folder (it holds the app's secrets and config-manager makes it owner-only); with none there the file is used for the run and not kept. A reason in the log names a fault by the file's own field names, never by a name the file made up. On any failure the app uses the last good copy, else the bundled file, and logs one line with the reason.
- Start-up never waits: `initModelRegistry` is offline and synchronous, and `src/main/index.ts` starts the read without awaiting it. When the read changes the registry, `sentinelModelDataChanged` closes the "not in the model picker" notice for a model the file now carries, at once.
- A model the file carries and this build does not is marked as added from the model data (`provenance.addedBy: 'model-data'`), as an overlay entry is, so the model list shipped with the build (which cannot name it) never reports it as possibly retired.

**Fable 5.2.** Added to `resources/model-registry.json` as the latest Fable (it takes the `fable` alias; 5.1 keeps its own id): 8 and 40 USD per million tokens in and out, 0.20 for a cache read. The cache write price (10) is the registry's usual 1.25 times the input price and the effort list is Fable 5.1's; neither was stated in the source used. The entry is marked `articleExempt` because the article copy shipped with the build (`resources/claude-code-model-configuration.json`, 2026-10-08) was taken before the article listed 5.2; refreshing that copy also means refreshing the saved article page the tests read, which was not done here.

**Not done.** The read uses the main process's own fetch, which does not go through a system proxy; behind one, the app stays on the last good copy or the bundled file. The Feature Guide, tips and README were not touched.

**Tests.** `tests/unit/model-data-schema.test.ts` (the rules, the join, the bundled file passing its own rules, no regular expression built), `tests/unit/main/model-data-fetch.test.ts` (the read, on a stand-in fetch: no request leaves the suite), `tests/unit/model-registry-remote-service.test.ts` (the real service) and new cases in `tests/unit/main/sentinel-model-findings-retire.test.ts` (the notice closes).
