## 2026-11-16 -- Machines page with This computer (2.1.3-beta.6, plan section C)

**Why.** The plan for beta.6 puts a session helper on each machine and a page that shows what it holds. Section C is that page. The helper work (section B) lands in parallel, so the page is built against a seam and a default source, and B plugs the real source in later.

**The seam.** `src/shared/machines.ts` holds the types the page and main share: `HeldSession`, `HelperState`, `SelfTestResult`, `MachineStatus` and `MachinesSource` (status, run the self-test, end a session, re-attach one). Four invoke channels carry them (`machines:status`, `machines:selfTest`, `machines:endSession`, `machines:reattach`), with a typed bridge in the preload and in `electron.d.ts`. There is no push: the page reads on open, on Refresh and after each action.

**Main side.** `src/main/ipc/machines-handlers.ts` registers the four doors from one source, read on every call, so a later `setMachinesSource(...)` shows at once. Section B imports `setMachinesSource` from that file. Until then `defaultMachinesSource()` answers: helper off (detail: the setting is off), nothing held, and End, Re-attach and the self-test refused in plain sentences. A source that throws or stays silent (8 s for a read, 15 s for End and Re-attach, 30 s for the self-test) reads as "The session helper did not answer." and never as a rejected call. End and Re-attach take only an id of a plausible shape, and index.ts passes the app window, so only the app's own main frame is answered.

**The page.** `MachinesPage.tsx` opens as a tab like the others. The nav rail button sits in the first group, right after Tokenomics (the group was a list written out three times in `SidebarNav.tsx`; it is now one constant). One card, This computer: the helper state in plain words (the Off sentence names the setting that switches it on), the helper version, the latest self-test with its time and a Run self-test button, and the terminals held, each with name, kind, start time, attached or waiting for the app, Re-attach and End. End asks first, in the row. An empty list says so in one sentence. The newest read wins, and every control is held while an action runs.

**Surface sweep.** An app-knowledge section (the page, that it holds only This computer in this beta, that the helper setting is off by default), a tip that goes once the page has been opened (a `machines.machines-page` usage id), the page's tab icon and label. The Feature Guide card is not here: a card needs a screenshot (`training-screenshots-exist`), and the screenshot is taken on the test VM for the owner to review, so the card goes in the release PR.

**Tests.** `tests/unit/renderer/machines-page.test.tsx` (every helper state, none, one, one left by a crash, failed, the helper missing, and each action), `tests/unit/main/machines-handlers.test.ts` (the default source's sentences, the doors, the failure and silence paths, ids, who may ask), `tests/unit/machines-bridge.test.ts` (channel names and the bridge), `tests/unit/renderer/machines-nav.test.tsx` (the rail, the tab, the tip and the knowledge text), and the existing tips list of navigable views gains `machines`. The Machines page is also in the e2e rail list.

**Not in this change.** The real helper source (section B), a push when the held list changes, and any machine other than This computer.
