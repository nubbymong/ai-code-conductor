## 2026-11-16 -- Machines page with This computer (2.1.3-beta.6, plan section C)

**Why.** The plan for beta.6 puts a session helper on each machine and a page that shows what it holds. Section C is that page. The helper work (section B) lands in parallel, so the page is built against a seam and a default source, and B plugs the real source in later.

**The seam.** `src/shared/machines.ts` holds the types the page and main share: `HeldSession`, `HelperState`, `SelfTestResult`, `MachineStatus` and `MachinesSource` (status, run the self-test, end a session, re-attach one), `MachineActionResult` (an interface, `{ ok, message? }`), the shape a held-terminal id must have (`HELD_SESSION_ID`, the helper protocol's session id, `^[A-Za-z0-9][A-Za-z0-9_-]{7,31}$`) and the one sentence both sides use when the helper does not answer (`MACHINES_NO_ANSWER`). Four invoke channels carry them (`machines:status`, `machines:selfTest`, `machines:endSession`, `machines:reattach`), with a typed bridge in the preload and in `electron.d.ts`. There is no push: the page reads on open, each time its tab comes back to the front, on Refresh and after each action.

**Main side.** `src/main/ipc/machines-handlers.ts` registers the four doors from one source, read on every call, so a later `setMachinesSource(...)` shows at once. Section B imports `setMachinesSource` from that file. Until then `defaultMachinesSource()` answers: helper off (no detail, the page's own Off sentence says where to switch it on), nothing held, and End, Re-attach and the self-test refused in plain sentences. A source that throws or stays silent (8 s for a read, 15 s for End and Re-attach, 30 s for the self-test, each pinned one millisecond either side) reads as "The session helper did not answer." and never as a rejected call. End and Re-attach take only an id of the protocol's shape, so a space, a control character, a leading dash or a string over 32 characters never reaches the helper. Every door answers only the app window's main frame; `getWindow` is a required argument, like every other handler that acts for the app.

**For section B.** The source must hand the page ids of the protocol's shape (the same string End hands to the helper's `end --session <sid>`), and the setting that switches the helper on must be called `Plain terminals through the session helper`, in Settings, General: the page, the tip and the Feature Guide text all name it. This PR should merge after B, or B must use that label.

**The page.** `MachinesPage.tsx` opens as a tab like the others. `App.tsx` passes it `active` (true while its tab is the one showing), because the app keeps an open page mounted behind another tab: the page reads again whenever `active` turns true, and reads nothing while it is behind another tab. The nav rail button sits in the first group, right after Tokenomics (the group was a list written out four times in `SidebarNav.tsx`; it is now one constant, and the collapsed rail reuses the two lists computed above it). One card, This computer: the helper state in plain words (the Off sentence names the setting that switches it on), any detail the source gives, the helper version, the latest self-test with its time and a Run self-test button, and the terminals held, each with name, kind, start time, attached or waiting for the app, Re-attach and End. End asks first, in the row.

An empty list says "holds no terminals" only when the helper is ready, off or not installed. A helper that is starting, failed or in a state this version does not know cannot list what it holds (main answers a failed read with no sessions), so the page says the list is not available instead of telling the user it holds nothing. A self-test this page ran is dropped when a read finds the helper no longer running, so Off never sits next to "Passed". The newest read wins, and every control is held while an action runs.

Keyboard and screen readers: the End question opens with focus on Keep it; Keep it puts focus back on that row's End; a confirmed End moves focus to the "Held terminals" heading (the row and its button are gone by then); opening the question on one row while another row's is open no longer hands focus to the other row. The confirm button's name starts with its visible words ("End terminal <name>"). The self-test result and the action notice sit in live regions that stay mounted and stay in the accessibility tree; the notice region sits inside the held-terminals block so the card's spacing leaves an empty one no room.

The expanded nav rail fits the sidebar. Its buttons are `flex-1 min-w-0 h-9` in a `gap-0.5` row (it was `gap-1`), and each icon sits in a `min-w-0` wrapper whose svg is `max-w-full h-auto`, so the icon shrinks with its pill. With the Account button showing the rail is ten buttons. Without `min-w-0` each is at least its 20px icon wide: at the old `gap-1` the row needed 241px against the 239px a 256px sidebar leaves (the row is the width less the 1px border and the 16px padding), so it spilled past the edge at the default width, and with the Account button showing it already overflowed at 200px before this page. With `gap-0.5` it needs about 221px, so without `min-w-0` it would spill only below about 238px. `min-w-0` alone left a second fault: each button was (W - 58) / 10 wide, under its 20px icon below 258px, so the icon stuck out of its pill and the Insights and Cloud Agents dots landed on it. Now a button is (W - 38) / 10 wide (the 1px border, 16px padding, the 1px divider and ten 2px gaps come off): 21.8px at 256, 19.2 at 230 and 16.2 at 200, the narrowest, and the icon is as wide as its pill up to 20px. The dots are children of the button, so they stay on the pill corner. That is the default UI scale (16px root font): at that scale no allowed width leaves the icon under 16px. The padding, the gaps and `h-9` are rem, so they follow the UI scale (0.8 to 1.3): at 1.3 the 200px minimum leaves the icon about 15.1px, a little under 16, and the row is 46.8px tall (36px at the default, 28.8px at 0.8; it was `py-2` round a fixed 20px icon, which is 40.8px at 1.3 and 32.8px at 0.8), as the collapsed rail's `w-10 h-10` already follow the scale. The icon fits its pill at every scale. jsdom does no layout, so the unit tests pin the classes and redo the arithmetic; the width itself is looked at on the VM UI check, at 256, 230 and 200 with two accounts and with Insights and Cloud Agents running, and once at scale 1.3 at 200.

**Surface sweep.** An app-knowledge section (the page, that it holds only This computer in this beta, that the helper setting is off by default, when it reads, what an empty list means), one sentence in "The pages on the left rail" (what Ask Conductor answers the rail question from), the guided tour's nav-rail step (it lists Machines), a tip that goes once the page has been opened (a `machines.machines-page` usage id), the page's tab icon and label. **Open item for the release PR:** the Feature Guide card. A card needs a screenshot (`training-screenshots-exist`), and the screenshot is taken on the test VM for the owner to review, so the card (a step in `training-steps.ts` with its `screenshotFilename`) goes in the release PR, with a README line if the shot is wanted there.

**Tests.** `tests/unit/renderer/machines-page.test.tsx` (every helper state including an unknown one, none, one, one left by a crash, attached with no tab, failed with and without a list, the helper missing; Run self-test, Re-attach and End, including a bridge that throws; start times for today, another day and a bad number; the focus and live-region behaviour; a stale self-test; a late older answer; reading again when the tab returns), `tests/unit/main/machines-handlers.test.ts` (the default source's sentences, the doors, the failure path, each door's own wait one millisecond either side, ids, who may ask on every door), `tests/unit/machines-bridge.test.ts` (channel names and the bridge), `tests/unit/renderer/machines-nav.test.tsx` (the rail and its fit, the tab, the App wiring, the tip and the knowledge text). The existing tips list of navigable views gains `machines`, the tour pin names Machines, and the e2e list gains a Machines page that must show its own card (Playwright is not run on the PC, so that one is unrun here).

**Not in this change.** The real helper source (section B), a push when the held list changes, the Feature Guide card, and any machine other than This computer.
