## 2026-10-13 -- 2.1.1 release text and the bare 2.1.1 version

- **What:** the stable 2.1.1 release text, written for someone coming from
  2.1.0, and the version moved from 2.1.1-beta.3 to 2.1.1. No product
  behaviour changes: text, docs, their tests and the version only.
- **Shape of the What's New entry:** one new entry, version `2.1.1`, on top
  of the 2.1.1-beta.1 to beta.3 entries, which stay as they are as the
  history. Why this shape:
  - release.yml passes the bare package.json version to
    `scripts/gen-changelog.js --notes`, so the qualification run (a bare
    version on the beta channel is tagged v2.1.1-beta) and the stable run
    (v2.1.1) both build their GitHub notes from this one entry;
  - the app diffs What's New from the last final release before a
    prerelease (whatsNewAnchorFor), so 2.1.0 users and beta testers alike
    land on 2.1.0 as their anchor; the summary page is curated in code, and
    this entry is what the Feature Guide, What's New, the full changelog in
    Settings, the GitHub notes and CHANGELOG.md show;
  - tests find the beta entries by version, and the drift guard keys on the
    newest entry's final release (2.1.1), which already has curated lines.
- **Known issues in the entry:** a changelog entry has only feature, fix and
  improvement rows, so each known issue is an improvement row whose text
  starts "Known issue:" (and the pinned Claude Code version starts
  "Notice:"). They show as Improved in the app and under Changed in the
  notes. A field of their own needs a renderer change, which is out of scope
  for this release.
- **Feature Guide (app-knowledge):** new Known issues entries for Check for
  Updates saying Up to date (after the move to the new repository name, a
  start while offline, or GitHub out of reach), for a Codex newer than the
  tested 0.156.1, and for 2.1.0 Codex users adding their account once; the
  macOS entry now sends a Mac on macOS 12 to 2.1.0, not to a prerelease; the
  FAT or network share entry no longer suggests a folder inside a user folder
  whose name holds characters outside plain English letters (it points at
  that entry instead). docs/USER_GUIDE.md gains a one-line pointer to the
  same entry. README: the Mac text and the tested Codex version.
- **Version:** package.json and package-lock.json root fields only;
  CHANGELOG.md regenerated with `npm run changelog`.
- **Left as is, on purpose:** the title bar and bottom bar Beta chips (they
  follow the update channel, not the version), the beta entries' own words
  (for example "stay on 2.1.1-beta.1" in the 2.1.1-beta.2 entry), and
  internal ids in a few test comments and two source comments (one is in
  the SSH code path, which would bring the SSH live matrix back into scope).
- **After the spec and code-quality reviews:** the summary and the Electron
  44 line say "on macOS 12, stay on 2.1.0", and the summary points at Known
  issues and workarounds instead of claiming every issue has a workaround;
  the non-English folder line keeps beta.3's own-disk condition; the README
  and the Mac entry name 2.1.1-beta.1 beside 2.1.0 as the last versions with
  the old Mac download name; the 2.1.0 Codex line says to turn Codex on
  before Add Codex account; the newer-Codex line and entry name the
  Providers card, and the entry says a closed account's card then shows its
  last reading; the SSH line covers an SSH Persistent session from before
  the update, and the zsh line keeps "at least when the app runs on
  Windows"; the first Codex line says Codex is local only, and the review
  line names the Codex-to-Claude direction as the new one. Each has a test.
- **Two known issues added after the reviews:** a Codex newer than 0.156.1 can offer a model the picker does not list yet (GPT-6.1-Sol), and Default: follows Codex is the way to use it; after an in-app update on Windows from 2.1.0 or a 2.1.1 beta, Vision can show Stopped when the app cannot get the list of running programs to identify the browser the earlier version left running, and the workaround is to sign out and back in, or restart.
