## 2026-11-16 -- Codex resume and resume list match a symlinked folder by real path (2.1.3-beta.6, plan section E)

**Problem.** A Codex conversation started in a symlinked folder (a symbolic link on macOS and Linux, a junction or link on Windows) records the link or the real folder, and the tab keeps the other. The resume lookup (`sameDirectory` in `providers/codex/rollout-lookup.ts`) and the resume list (`samePath` in `scripts/lib/codex-resume-picker-lib.js`) compared the spelling only. So the lookup set `cwdMismatch` and started in the configured folder (a resume by id still worked), and the list did not offer the conversation at all. beta.5 fixed the status-line claim only and left this as a follow-up (`2026-11-15-accounts-and-sessions-307.md`, "Not in this change").

**Change.**
- The folders are compared by exact spelling first, then by real path. The real path is asked with `fs.promises.realpath` (never the synchronous call), once per spelling per lookup, with a bounded wait (`CODEX_REAL_PATH_WAIT_MS`, 1.5 s, the repo's `withPathWalkDeadline`). A path that cannot be resolved (missing, refused, no answer in time, relative, a network share) is compared by its spelling alone, as before.
- Resume lookup: the launch builder (`buildCodexSpawn`) is synchronous and `pty-manager.ts` may not grow, so the look is made where the launch already waits for the node.exe lookup: `ipc/pty-handlers.ts` awaits `provider.warmResumeLookup` (new, optional) before `spawnPty`. `warmCodexResume` finds the conversation's rollouts, compares by real path, and keeps the rollout it would take for 30 s. `resolveCodexResume` reads that answer once; with none it walks and compares by spelling exactly as before. The realm is walked once per launch either way (the warm-up's walk is the one the builder skips).
- Which conversation is warmed mirrors `pty-manager.ts`: the request's own `resume`, else on a restart the kept one, never after the picker or a fresh-conversation respawn; an Ask launch is left to the spelling.
- Resume list: `walkRolloutsAsync` (new, the picker script uses it, with `walkRollouts` as the fallback on any error) lists a rollout whose recorded folder is the same real folder as the session's folder or a git worktree. A folder a rollout records that is already a worktree's real folder is matched with no disk call. After one folder does not answer in time, no NEW folder on the same drive is asked, while an answer already had is still given (a timeout never hides a conversation whose folder is already known). `walkRollouts` itself is unchanged (it now shares the new `rolloutHeads` generator).
- Status-line claim: unchanged. It keeps its own synchronous per-watch cache in `telemetry.ts`; `sameFolderByRealPath` only shares the new `isLocalAbsolutePath` rule.

**Not changed.** The launch builder still runs `isHomeOrAncestor` (a synchronous real-path read, the home-folder guard) and a `statSync` existence check on the tab's folder, and the sessions-folder walk is still synchronous; those predate this change and are not folder matching.

**Tests.** `tests/unit/providers/codex/resume-real-path.test.ts` and `tests/unit/scripts/codex-resume-picker-real-path.test.ts` (a stand-in for the real path, run anywhere, including the bounded wait, once per folder, no synchronous call, TTL and read-once). `tests/unit/main/pty-spawn-warms-codex-resume.test.ts` (the real `pty:spawn` handler with a stand-in provider: it waits for the look, names the request's own or the kept conversation as pty-manager does, skips the picker, a fresh respawn, SSH and Ask, and survives a look that fails). `tests/unit/providers/codex/resume-real-path-links.test.ts` (host quarantine: a real symlink on macOS and Linux, a real junction on Windows, both ways round, a link whose folder is gone, the list, and no synchronous call). The links file has only run in CI; the Windows junction case is its first Windows run.
