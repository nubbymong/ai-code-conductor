## 2026-11-15 -- Rust helper skeleton, its CI job and probe P7 (2.1.3-beta.5, section B)

**Problem.** ADR-029 and ADR-030 make a Rust helper the owner of every held terminal session, and say it "lands dark": a pinned project, CI on every host target, shared message fixtures, nothing bundled. At 64dec172 there was no Rust in the repository at all, only the protocol (`docs/remote/helper-protocol.md`) and the threat model. Probe P7 (does a detached holder survive the app quitting and the installer running, on Windows) also had no procedure, and it decides how the next beta starts the helper holding local sessions.

**Change.**

- `helper/` is new, a top-level folder (not under `src/` or `resources/`). One Cargo package with a library and two programs: `aicc-helper` and `aicc-fake-cli` (a stand-in provider CLI for tests and probes). `rust-toolchain.toml` pins 1.90.0.
- Frame codec (`src/frame.rs`): the layout of protocol section 6, including the 4-byte channel id (4-byte big-endian length of the rest, kind byte, channel, payload). JSON 1 MiB helper to app and 16 MiB app to helper, raw 64 KiB both ways, depth 32. A length over the limit or under 5 is refused on the four length bytes, before anything is allocated. `src/json.rs` is a small reader and writer of our own, so there is no JSON crate.
- Hello (`src/hello.rs`): `AICC-HELLO <nonce> <json>` (at most 4 KiB), the strict reader the app will mirror (another sid, another nonce or a broken schema is `no-hello`; unknown fields ignored), `hello.ack`, highest-common version choice, `error` text capped at 512 characters, `AICC-RESULT` lines.
- Output ring (`src/ring.rs`): 2 MiB, bytes at fixed offsets, replay from an offset, an offset older than the ring is answered from `ring_start` with `truncated` set, one past the end is refused.
- Terminal (`src/pty/`): `openpty` on Unix, ConPTY on Windows, written against `libc` and `windows-sys` directly. Holder (`src/holder.rs`): holds one terminal and child, attach with replay then live output in one critical section (no gap, no repeat), detach keeps the child, the newest attach replaces the older (its live channel closes). Exit is watched by polling, because the ConPTY output pipe does not end when the child does.
- Self-test (`aicc-helper selftest`): codec, hello, ring and a terminal hold, detach, re-attach round trip, one `AICC-RESULT` line.
- Probe transport (`src/dirhold.rs`, `src/detach.rs`): `hold [--detach]`, `attach`, `end` through files in a session folder, so a probe can attach from another process after the one that started the holder is gone. It is a stand-in for the local socket or named pipe, which is a later slice.
- Shared fixtures `helper/fixtures/{frames,hello,limits}.json`, read by `helper/tests/fixtures.rs` and by `tests/unit/scripts/helper-fixtures.test.ts`. The vitest side decodes every vector with a reader written from the document (not the Rust code), and checks `limits.json`, the protocol document and the numbers in the Rust source against each other.
- `ci.yml`: a new job `Helper (os)` on windows-2025, macos-latest and ubuntu-latest. It starts on a push and on a pull request, except for a label change other than `ci-run` and an edit that is not a base change (the Test jobs' own rule, so a label or title change does not rebuild three runners); it then decides inside the job (`scripts/ci/helper-scope.mjs`, same pattern as `change-scope.mjs`) and every later step skips on the literal `helper=false`. Not a required check, no job-level path filter, the `Test (os)` jobs are unchanged and its name does not match the release gate's `Test (` pattern. Actions are pinned by commit. Without `helper/Cargo.lock` it runs `cargo generate-lockfile`, uploads it as `helper-cargo-lock` (Linux job) and fails saying to commit it; with it, every build and test runs `--locked`. It counts the lock file's packages and fails above 24, fails on any networking type in the source, and uploads the Windows build as `helper-windows` (with the probe script).
- `tests/unit/scripts/helper-not-shipped.test.ts` fails if `build.files`, `extraResources` or `extraFiles` would take anything under `helper/`, or `helper/` moves under `resources/` or `src/`.
- `helper/probes/p7-windows-survival.ps1` and its README: given the `helper-windows` artifact and an installer, start a detached holder with the fake CLI as its child from a stand-in "app", kill that app's whole process tree, run the installer silently, and report whether the holder and child survived each step and whether re-attach replays. It is run on the Windows VM later.
- `AGENTS.md` gets one Architecture line for `helper/`.
- Review fixes: on Windows the starter clears the inherit flag on its own three standard handles before it starts a detached holder (std starts children with handle inheritance on, so a holder started from a command whose output was piped kept those pipes open until it ended, and the caller waiting for end of file never returned); the two detach tests also send the starter's output to files. The probe transport writes the ring's replay to `out.bin` before it mirrors live output (`dirhold::start_mirror`), so a banner printed between the child starting and the mirror attaching is not lost. Probe P7 no longer reuses the parameter name `$Installer` for the installer process (PowerShell variable names ignore case, and the typed parameter turned the process into text).
- `.gitignore` gains `helper/target/`, and an exception for `helper/probes/*.ps1`: the repo-wide `*.ps1` rule would otherwise have left the probe script out of the commit (a test now checks that every helper file is tracked and the build output is ignored).

**Where the plan and the documents differ.** The documents win. The plan's one-line frame description left out the channel id; the protocol has it. The plan said replay "from `since_seq`"; in the protocol `since_seq` belongs to the event spool and the terminal replays by byte offset (`attach --from <offset>`, `ring_start` and `ring_end`), so the ring replays by offset and the event spool is not built. A PTY crate of the portable-pty class was suggested; its lock set (anyhow, nix, serial2, shared_library, winapi, winreg, thiserror and the proc macros behind it) sits at the 25-crate limit and brings procedural macros, so the PTY layer is written on `libc` and `windows-sys` instead: the lock file is expected to hold 12 packages.

**Not in this change.** There is no `Cargo.lock` (no Rust toolchain on the machine that wrote this; the first CI run generates it as an artifact and fails until it is committed). The Rust was written without being compiled: the first CI run is its first build, on all three OSes, and may need fix-ups, the Windows ConPTY file most of all. No signing, hash manifest, seccomp, cargo-deny, cargo-audit or cargo-vet; no local socket or named pipe; no `serve`, `emit` or `mcp`; nothing in `src/` calls the helper; the P7 probe has not been run and the ADR-030 probe table row for P7 is filled after it runs on the Windows VM. `helper/Cargo.lock` is committed from the first CI run's `helper-cargo-lock` artifact before merge; the README and `Cargo.toml` already say it is committed. Any `Cargo.lock` change is a security review item at the stable round.

**Tests.** `tests/unit/scripts/helper-scope.test.ts`, `helper-ci-job.test.ts`, `helper-fixtures.test.ts`, `helper-not-shipped.test.ts`, `helper-probe-p7.test.ts` (no local reuses a parameter name; each new case was red under a mutant of the new code); `cargo test` in `helper/` (unit tests in each module, `tests/fixtures.rs`, `tests/hold.rs`, `tests/probe_transport.rs`, whose tests take one lock so only one starts processes at a time: on Windows a child inherits every inheritable handle, and a holder started beside another test thread mid-spawn could carry that thread's pipe ends and delay it) runs in CI only.
